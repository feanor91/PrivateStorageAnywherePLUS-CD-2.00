# Port to Crimson Desert build 3527 (4 November 2026 update)

Three game updates followed 3460. **3462 and 3479 needed no change at all**:
the user re-ran `MAJ-mod.bat` and every anchor re-derived on its own
(`patched/build-3462.txt`, `patched/build-3479.txt`, both 91 manager globals,
no `STOP`). 3479 was confirmed in game — `slot patcher -> 8`,
`InventoryInfo slot patch: 8 entries default 10 -> 1000`,
`HOOK CanShow: OK slot base+0x59EBF48 -> detour (orig +0xEE3380)`.

3527 stopped the build on one line:

```
STOP: manager window 0x71ae000..0x13812000 is not inside one data section
```

## One obfuscation stub inside the look-back window

`derive_manager_window` finds the block of StaticInfoManager pointer globals by
scanning for the bucket idiom `shl r11,8 ; add r11,[r10+0x78]` and taking every
`mov r10,[rip+G]` in the 0x60 bytes before it. The cluster is then padded by
64 KB each side and must sit inside one data section.

On 3527 one extra candidate appeared, and it dragged the window from
`0x71c3220` out to `0x13801...`:

```
0x8881600  89e3                 mov ebx, esp
0x8881602  47bf079d4c8b         mov r15d, 0x8b4c9d07
0x8881608  2424                 and al, 0x24
0x888160a  4c891424             mov qword ptr [rsp], r10
0x888160e  4c8b1516fbf70a       mov r10, qword ptr [rip + 0xaf7fb16]   -> 0x1380112b
0x8881615  4981eaa9d69cf8       sub r10, -0x7632957
0x888161c  4c871424             xchg qword ptr [rsp], r10
0x8881620  48810424626367fd     add qword ptr [rsp], -0x2989c9e
0x8881628  c3                   ret
0x8881629  0f1f8000000000       nop
0x8881630  <next function, whose bucket idiom is at 0x888166e>
```

This is one of the game's control-flow obfuscation stubs: it loads a value,
subtracts a constant, swaps the result onto the stack and returns to it — a
computed return address. Three things make it worth recording:

- **It is a real instruction.** No instruction-boundary check, no
  disassembler sync, no `.pdata` lookup would have rejected it. `pdata` in
  fact has no entry covering `0x888160e` at all, so a boundary test would have
  had nothing to anchor to.
- **It is not in the same function as the bucket idiom.** The idiom at
  `0x888166e` belongs to the function starting at `0x8881630`; the stub ends
  at `0x8881628`. The 0x60-byte look-back crossed the boundary.
- **Its target is not a pointer global**, and says so twice over:
  `0x1380112b` is not 8-aligned, and it lands in `.text`.

## The fix: filter candidates by what the idiom does with them

The idiom goes on to dereference the loaded value as `[r10+0x78]`, so the
value must be a qword in data. Two conditions, both facts about the shape
rather than thresholds: **8-aligned**, and **in a non-code section**. The
genuine 91 globals satisfy both; the stub's target fails both.

`data_section_of(g, rva)` is the new helper (the section holding an rva, if
that section is not code), and the window containment check now uses it too
instead of repeating the test inline. Dropped candidates are reported rather
than hidden:

```
manager globals: 91 distinct, 0x71bee10..0x71de218; dropped 1 non-pointer
candidate(s): 0x1380112b at 0x888160e
```

Had the real cluster been the thing that moved, the count would have fallen
below 10 and the build would still have stopped — the `too few manager
globals` guard is unchanged.
