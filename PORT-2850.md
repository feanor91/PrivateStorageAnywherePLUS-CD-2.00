# Port to Crimson Desert build 2850 (September 2026 update)

Unofficial re-targeting of the tested 2.00 release (build AX, sha256 `c2b9848f…`)
to the game build with `FileVersion 1.0.0.2850` / `SizeOfImage 0x16B0E000`.
The step-by-step procedure for the next game update is in [PORTING.md](PORTING.md) (French).
No pristine v1.5.10 input is needed: `tools/retarget_ay.py` works on the AX ASI
(`original/PrivateStorageAnywhere-AX-2.00.asi`) and derives every game-side
value from the executable. Deterministic; every build below reproduces bit for bit.

## INI requirement on this build

`PrivateStorageExpansions` must be set to the real number of purchased
expansions (`0` if none) instead of the release default `-1`. With `-1` the
worker waits for the first F4 open before writing the base, which is after the
save has built the private-storage container: the label then shows the new
total but items cannot be moved in. With an explicit value the base is written
about one second after `READY!`, before the save loads, exactly like the
housing chests. Evidence: `docs/logs-2850/log-BB-on-2850-PASS.txt` line 41,
`[PRIV] … base 240 -> 1000` logged between `[INV]` and the housing patch, i.e.
before any panel was opened; the later open reports `base=1000`.

## What moved between 2.00 and 2850 (all derived, not typed)

- mainChar global `0x6330A78 -> 0x6C2DA48` (the mod's own scanner pattern no
  longer exists; replaced by a direct store of the profile-derived value)
- ModeSwitch `0x530E20 -> 0x5CF8C0`, mode object `[parent+0x1158] -> [+0x1178]`
- ResolveActor `0x75BF90 -> 0x83D990`, CampWareHouse `0x501C6B8 -> 0x57A3658`
- mode-state layout, in-game mode 4 and store sub-mode 5: unchanged
- InventoryInfoManager: no static route (base ctor in the obfuscated section,
  instance registered into a container). Resolved at runtime by matching the
  object's vptr against the RTTI vtable `base+0x57A37D0`; found at `0x6C2E2C8`
- NameToKey: not re-anchored. The CampWareHouse InventoryKey is the constant 8
  (2.00 value, recurring immediate in the 2850 consumers); validated by the
  wrapper's bucket walk and by the dry run (`base=240 max=1000`)

## Known cosmetic lines

- `[MODE] capture hook NOT armed (stage 3)`: VirtualAlloc found no page in the
  16 attempts below the image; the fallback route reads the right mode.
- `CHAN PRE/POST EXCEPTION`: the original mod's read-only, SEH-guarded probe on
  stale 1.05 handler offsets. Nothing is written.
- `[PRIV] … tot=0 base 240 -> 1000` repeated in the BA dry run only.
- `[PRIV] exp=4294967295 …` on the boot-time write: the AX log line prints the
  expansion cache (-1) instead of the value actually used (the INI override).

Logs for every step are in `docs/logs-2850/` (as `.txt`, since `*.log` is
git-ignored) with the INI used.
