# Port to Crimson Desert build 3446 (30 October 2026 update)

The first update that made the game **crash on launch** with the mod
installed, rather than merely stop working. Procedure in [PORTING.md](PORTING.md).

The installed build was `CD 2976.BC`. Its log reaches `READY!` and stops.

## Root cause: the CanShow hook guessed a prologue length

The upstream installer asks `FindPrologBoundary` for an instruction boundary
at or past 14 bytes and, when that fails, logs

```
  FindPrologBoundary: unknown opcode 0x74 at pos 10
HOOK CanShow: prolog boundary not detected (got 0), falling back to fixed 14 bytes
HOOK CanShow: OK base+0xA277270 (size=14)
```

and hooks anyway. On 3446 that function begins:

```
+0   mov rax,[rcx+8]            (4)
+4   mov r9,rcx                 (3)
+7   test rax,rax               (3)
+10  je rel8                    (2)   <- relative branch inside the stolen bytes
+12  movzx r8d,word [rax+0x8a]  (8)   <- the 14-byte cut splits this instruction
```

Fourteen bytes therefore (a) end mid-instruction, so the trampoline's tail is
garbage, and (b) relocate a `je rel8` whose target is computed from the
original address. Either is fatal, and CanShow runs immediately. The other two
hooks take 15 bytes and land on clean boundaries, which is why only this one
breaks.

**Fix:** `mov esi,0xE` at ASI `0x601E` is five bytes, exactly a `jmp rel32`, so
the fallback now jumps to the installer's own ABORT path at `0x61B3`. The hook
is not installed and the mod continues without it. Applied to every build, not
just this one: guessing a prologue length is unsafe on any version, and on
builds where the boundary is found the patch changes nothing.

## Second change: the sub-mode count is not fixed

The build also stopped on

```
STOP: layout invariant failed: dirty == subtypes + 0x23
      ({'mode': 48, 'submode': 50, 'flags': 58, 'subtypes': 65, 'dirty': 102})
```

The sub-mode jump table grew from 17 to 18 entries. `subtypes[n]` is followed
by its shadow copy and then `dirty`, so the gap is `2*n + 1`: `0x23` for 17,
`0x25` for 18. The invariant now derives `n` from the sub-mode table instead of
hardcoding the gap, and the two tables are told apart by which one emits
`ingame-global` rather than by their size (both carry a `store` entry).

Every earlier build satisfies the general form: 2850 `0x38 + 35 = 0x5B`,
2944/2976 `0x39 + 35 = 0x5C`, 3446 `0x41 + 37 = 0x66`.
