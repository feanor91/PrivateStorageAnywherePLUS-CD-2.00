## Symptom on the 2850 build (BB `02b44e3f…`)

Startup completed (`READY!`) but every F4 gave `NOT READY: mainChar`: the
mainChar global baked for 2850 pointed at nothing on 2944. The capture hook
refused to arm at stage 2 (prologue bytes changed) — the guard worked, nothing
was written.

## What moved, and what the script had to learn

1. **UI tag pool reordered.** `store` now sits 0x70 bytes *before*
   `ingame-global`; `derive_modestate.find_tag_pool` searched only
   `[-0x40, +0x180]` around the anchor. Widened to ±0x200.
2. **Jump-table bounds.** `read_jump_tables` paired `cmp` immediates with
   tables by order; with the merged `.pdata` ranges the pairing was off and
   the mode table was read as 4 entries. Each table is now bounded by the
   `cmp r8,N` immediately preceding its own dispatch: mode table 7 entries
   with `[4]=ingame-global`, sub-mode table 17 entries with `[5]=store` —
   values unchanged.
3. **A byte inserted between mode and sub-mode.** The mode-state struct is
   now `mode +0x28`, a transition byte `+0x29` (idles at 7 = "none"),
   `sub-mode +0x2A`, `flags +0x32`, `subtypes +0x39`, `dirty +0x5C`.
   `derive_from_modeswitch`'s adjacent-store rule picked `+0x29/+0x2A` (the
   first adjacent pair in address order) and the mod read "mode 7" — hence the
   BLOCKED first build. The script now takes the pair ModeSwitch loads into
   `edx`/`r8d` right before calling `BuildModeTagList` (`+0x28`, `+0x2A`),
   without requiring adjacency, and checks `mode < submode <= mode+2`,
   `flags == submode+8`, `subtypes == flags+7`, `dirty == subtypes+0x23`.
   Because the layout differs from AX's, the script re-emits it: the four
   immediates of the layout stub (A), the two `mov byte [r9+dirty],1` stores,
   and the diagnostic probe's guards and reads.
4. **ModeSwitch recompiled** (`0x640DC0`, prologue `mov [rsp+0x18],rbx ;
   push rbp ; push rsi ; push rdi …`, two direct callers). The 8-byte capture
   hook is not applicable; it stays disarmed (stage 2) and the fallback route
   `[root+0x90]+0x1188` is used — the mode-object offset is read from the
   call sites (both agree), and menuMgr's neighbouring fields all moved by
   +0x30, consistent with `+0x1158 → +0x1178 → +0x1188`.
5. Build tag now comes from the executable's `FileVersion` (`CD 2944.BB`).

Everything else derived unchanged: mainChar `0x6D69208` (983 loads, same
profile), ResolveActor `0x8B4480`, CampWareHouse `0x58B9ED8`,
InventoryInfoManager vtable `0x58BA020` (found at runtime at `0x6D69AA8`),
manager window `0x6D59000..0x6D9B000`, CampWareHouse key 8.
